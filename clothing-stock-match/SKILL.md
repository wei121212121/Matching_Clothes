# 服装找款与配货标注工作流

## 目标与边界

从用户指定的本地图库中为每张实拍图寻找**同款**款式图；颜色允许不同。匹配依据是印花/文字、图案位置、领口、版型、口袋、纹理和条纹等款式特征，不能只凭颜色或“看着相似”确认。

- 图库是动态的：每次以用户当前选择的文件夹为准，不假定固定图库或永久有效的款式。
- 不修改图库原图、实拍原图、原文件名；输出仅写入用户选择的结果目录。
- AI 候选是供人工确认的排序，不把低分候选自动当成同款。
- 仅在用户明确要求时才处理未匹配项；未匹配应输出带“未匹配”红字的实拍图，而不是猜测某一款。

## 推荐操作流程（V8 对比界面版）

1. 选择本次的“款式图库”和“结果目录”。图库更新后点击“建立/更新索引”；未变更时复用已有索引。
2. 导入实拍图：优先拖入；不支持时可复制文件后在左侧列表按 `Ctrl+V`，也可导入单图或整个文件夹。
3. 点击“分析新照片（F5）”。只分析新加入且尚未分析的照片，已确认或已有候选的照片不重复计算。
4. 从左到右核对：实拍图 → 右侧候选/结果预览 → 候选列表。默认一次显示 20 款；没有正确款时继续“再显示20款”，新候选接在已看候选之后。
5. 找到正确款后双击候选或点击“确认候选”；难以确认时用“手动选择款式图”；图库确实没有时用“未匹配”。
6. 逐张复核颜色、尺码数量和其他文字。确认后默认进入下一张；可取消“确认后到下一张”以停留检查。
7. 全部确认后点击“导出本批全部结果（Ctrl+E）”。如仍有待确认照片，先提示用户选择返回确认或明确忽略。

## 匹配判断

1. 颜色只作弱证据。同款不同色、拍摄角度、模特图与挂拍图都不能单独否定同款。
2. 优先核对不可替代特征：主图案/人物、稳定文字、印花位置、领型、门襟、口袋、条纹方向和特殊肌理。
3. 至少有两个独特特征一致，或“不可替代的主图案/文字 + 版型或领口”一致，才可确认。
4. 候选不足时继续展开候选或手动选择；不要为了清单完整而把相似款确认成同款。
5. 人工确认过的实拍—款式关系可作为当前图库的本地反馈样本；换图库后不得把它当作该新图库的事实。

## 颜色、尺码与文字

- `M2` 表示 M 码 2 件；`XL2` 表示 XL 码 2 件；`2XL1`、`3XL1` 同理。保留同一张图中所有有数量的尺码。
- 优先读取实拍图上的**红色人工标注**：先提取其中明确写出的颜色和尺码数量。
- 红字里有颜色（如“黑色”“浅灰”“绿”“卡其”）时，它优先于画面自动颜色判断；未读到颜色文字时，才以衣服主体的画面颜色作预填建议。
- 自动读取只是预填。用户能直接修改颜色、M/L/XL/2XL/3XL 数量和其他文字；只有填写数量的尺码才会标红。
- 预设颜色为黑色、白色、灰色、卡其；其他颜色保留为“其他文字”，不要强行归类。
- 其他文字可输入任意内容并原样标注；不能把没有数量的款号或普通数字误当作尺码数量。

## 标注与导出

1. 用直接像素叠字生成结果，不使用图片生成模型。
2. 结果图以确认的款式图为底图；同款不同色仍使用该款式图，并叠加实拍图的颜色、尺码数量和其他文字。
3. 红色标注应居中、清晰、不过粗，尽量避开关键印花；预览可滚轮缩放、拖动、双击恢复以检查细节。
4. 匹配结果保留款式图原文件名；未匹配结果保留实拍图原文件名。每次导出建立独立任务文件夹，并输出任务明细和补货汇总。
5. 导出前快速检查：款式图是否选对、颜色/尺码是否齐全、预览文字是否可读、结果路径是否正确。

## 交付与安全

- 回答用户时给出结果图片、对应文件名和绝对保存路径；用户只要名称时只给名称。
- 不删除或覆盖用户原始图片、图库、模型、索引或已有结果。
- 源码、脚本、说明与本 Skill 可以提交 Git；原图库、实拍图、模型、缓存、`build/` 和 `dist/` 不提交。
