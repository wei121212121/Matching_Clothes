# V8 优化笔记

## 目标

V8 面向不断变化的任意服装图库，不绑定当前 170 张图片，也不写死款号、文件名或正确答案。实拍案例只用于覆盖常见难点：同款不同色、印花位置变化、小胸标、满版纹理、条纹、拍摄角度、光照和红色尺码文字干扰。

V7 保持原样。V8 使用独立的设置、索引、OCR 缓存、预览缓存和人工确认记录。

## 整套流程优化

1. 导入图片支持按钮、文件夹、资源管理器拖入和复制后 Ctrl+V。
2. “分析新照片”只处理后来加入且尚未分析的图片，不重复计算已有候选或已确认结果。
3. 待确认项目排在前面，并显示总数、待确认、已确认和未匹配数量。
4. 候选默认显示 20 款；继续展开时直接定位到新增候选，不从第一款重新浏览。
5. 确认、手动选择和未匹配操作固定在候选预览上方，竖图不会把按钮顶出屏幕。
6. 确认后可自动进入下一张待确认图片；也可关闭自动前进，留在当前预览复核。
7. 未匹配会立即生成带“未匹配”红字的预览，保证每张实拍都有可检查结果。
8. 导出按钮固定在窗口底部；小屏幕同时保留页面纵向和横向滚动条。
9. 导出前若仍有待确认图片，必须明确选择返回或忽略后继续。
10. 输出使用图库原文件名；未匹配使用实拍原文件名，不修改原图库和原实拍图。

## 通用视觉匹配优化

- 使用离线 SSCD 四视角特征：整件、中央图案、上半身、小胸标。
- 保留低权重纹理特征，帮助条纹、洗水、满版图案和面料纹理款。
- 自动弱化实拍图已有的红色尺码标注，避免红字成为错误的主特征。
- OCR 提取衣服图案中的英文和数字，在文字证据可靠时参与重排。
- 降低颜色对款式匹配的影响，使黑/白、黑/灰等同款不同色仍能靠图案和结构匹配。
- 人工确认会保存为当前图库的本地实拍范例。以后遇到相似实拍时，只对已确认的目标款做受控加权。
- 本地范例按图库完整路径隔离；更换图库不会沿用旧图库的答案。
- 图库增删图片后可增量更新 OCR 缓存；索引版本变化时会安全重建。

## 模型选择记录

对 SSCD 多视角和 DINOv2 方案做过本机 CPU 对比。DINOv2 在小胸标案例中明显靠后；SSCD 四视角对商品图与门店实拍的域差异更稳，因此 V8 保留 SSCD，并用局部视角、OCR 和轻量纹理做融合。没有加入只适合当前图库的款号规则。

## 验证结果

- Python 编译检查通过。
- 原图不被覆盖、输出文件名不变检查通过。
- 文件夹导入、复制粘贴和安全拖入检查通过。
- 700×480 小窗口且已加载竖图时，确认操作和底部导出按钮仍可到达。
- 本地确认范例学习、图库隔离和黑/白/灰识别回归检查通过。
- 历史四个已知对应案例中，三例正确款排到第 1；满版纹理案例的图库图案被巨大红色遮挡，排名仍较后。该情况保留人工从前 20 款继续展开或手动选择的兜底，不以写死答案处理。
- 新提供的 16 张案例用于图像解码、四视角特征、OCR/尺码和颜色流程覆盖；其中可能没有图库对应款，因此不把“必须匹配某文件”作为测试条件。

## 已知边界

- 图库中没有对应款时，模型无法凭空生成正确款，应使用“未匹配”。
- 图库图片本身被大面积红字、裁剪或遮挡时，视觉证据不足，正确款未必排在首位。
- 首次更换大图库需要建立索引；以后图库未变化时直接读取缓存。
- 本地学习需要至少一次人工选对，且只帮助相近实拍，不会取代人工最终确认。
