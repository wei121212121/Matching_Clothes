# 开发与打包

## 当前维护版本

`clothing_matcher_v8_ui_alt` 是当前维护的 V8 对比界面版。`clothing_matcher_exe` 为历史代码，只用于回溯，不建议继续叠加功能。

## 开发环境

```powershell
cd clothing_matcher_v8_ui_alt
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
python app.py
```

主要依赖是 Pillow、NumPy、ONNX Runtime、RapidOCR ONNX Runtime、tkinterdnd2 和 PyInstaller。

## 架构

- `app.py`：窗口布局、导入、候选交互、人工确认和导出流程。
- `engine.py`：图片遍历、视觉特征、OCR、候选融合、本地反馈、颜色判断和结果绘制。
- `%LOCALAPPDATA%\ClothingMatcherV8`：设置、索引、OCR 缓存、预览和反馈数据。
- `models/`：本地模型文件；不提交 Git。

## 本地验证

```powershell
python -m py_compile app.py engine.py verify_imports.py verify_export.py verify_v8.py
python verify_v8.py
python verify_imports.py
python verify_export.py
```

完整回归依赖仓库根目录下的本地测试图库，部分颜色/反馈案例还会在临时目录中查找测试照片。它们都不属于公开仓库。测试产物写到 `.verification/` 并被 Git 忽略。

## Windows 打包

将模型放到 `models/` 后执行：

```powershell
.\build.ps1 -AppName ClothingMatcher_V8
```

也可以指定模型：

```powershell
.\build.ps1 -AppName ClothingMatcher_V8 -ModelFile C:\Models\sscd_disc_mixup.onnx
```

如果不提供模型且默认模型不存在，脚本仍会打包轻量模式。输出位于 `dist/<AppName>/`，`build/` 和 `dist/` 不提交 Git。

## 修改原则

- V8 与历史版本的设置、索引和反馈目录保持隔离。
- 匹配规则不能绑定某个固定图库、款号、文件名或已知答案。
- 颜色不得成为确认同款的主要依据。
- 不修改原图；所有测试结果写入忽略目录。
- UI 修改必须验证小屏幕、图片已加载、滚动条和底部导出按钮可达。
- 新的人工确认学习只能在当前图库范围内生效。

## 发布检查清单

1. `git status --short` 中没有图库、实拍图、结果、模型或凭据。
2. 运行语法检查和可用的 V8 验证脚本。
3. 用至少一张竖图检查预览缩放、拖动、分隔栏和固定导出按钮。
4. 确认 README、使用手册与实际界面一致。
5. 本地打包后在没有 Python 的 Windows 环境验证启动。
6. 再提交和推送；大型模型应由拥有合法分发权的一方单独提供。
